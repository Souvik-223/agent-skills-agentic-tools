## CUSTOM SECURITY SCAN INSTRUCTIONS
## Appended to default security-review categories for Full-Stack, RAG, and MCP Architectures.

---

**RAG Pipeline Security:**
- Prompt injection via user-controlled input injected into LLM system prompts without sanitization or boundary markers
- Vector store poisoning — untrusted content written to embedding databases that could corrupt retrieval results
- Retrieval manipulation — crafted inputs causing RAG pipelines to return malicious or biased external context
- Context window exfiltration — injected instructions in user input designed to leak system instructions or session data

**MCP Server & Tool Security:**
- Tool parameter injection — MCP tool arguments executed without validation in subshells, filesystems, or databases
- Unauthenticated tool exposure — MCP tools accessible without proper transport authorization
- Tool output tampering — MCP tool results containing malicious scripts or unsanitized markdown executed in client contexts
- Excessive permissions — MCP tools granted filesystem write or network access outside intended workspace boundaries

**API & Backend Security:**
- Schema bypass — disabling strict validation or allowing unvalidated arbitrary dictionary inputs
- Background task injection — untrusted input passed to async background tasks without parameter verification
- Dependency override exposure — test-only mock dependencies left active in production entry points
- Server-Sent Events (SSE) / WebSocket injection — unsanitized streaming payloads rendered directly on client frontends

**Data Integrity & Privacy:**
- Unfiltered logging of sensitive data (passwords, tokens, PII, API keys) in application logs or vector databases
- Multi-tenant data leakage — ensuring user IDs and tenant filters are strictly enforced across all database queries
- File upload vulnerabilities — missing MIME-type validation, path traversal on filename saving, or uncompressed zip bombs
