## SECURITY REVIEW — FALSE POSITIVE FILTERING INSTRUCTIONS
## Generic Baseline: Web APIs (FastAPI/Node), Modern Frontends (React/Vue), RAG Pipelines, and MCP Servers

---

HARD EXCLUSIONS

1. All default exclusions from the base security-review command apply (DOS, rate limiting, resource exhaustion in local development).
2. Automatic input validation via schemas/types (e.g., Pydantic in Python, Zod/TypeScript in Node) — do NOT flag missing manual validation when validated schemas handle it.
3. Modern frontend framework template bindings (JSX/React, Vue template `{{ }}` / `v-bind`) — frameworks escape by default. Only flag explicit raw HTML injection (`dangerouslySetInnerHTML`, `v-html`).
4. Local MCP server tool definitions — tool parameter schemas are not attack surfaces from untrusted external users unless explicitly exposed to public network gateways.
5. Strict type hints and schema constraints — these are validation guards, not security vulnerabilities.
6. Curated reference database read operations — internal reference lookups are not user-controlled injection points.
7. Internal RAG pipeline prompts — passing retrieved context into system prompts is standard architecture; only flag if untrusted user input is concatenated without sanitization or boundary fencing.
8. Environment-based configuration (secrets/API keys via `.env` / `os.environ` / secret managers) — assumed secured at infrastructure level.
9. Local development endpoints without explicit rate limiting — rate limiting is typically enforced at API gateway / reverse proxy level.
10. CORS configuration in development profiles — only flag if wildcard CORS is used in a configuration explicitly targeting production.

---

SIGNAL QUALITY CRITERIA

1. Dependency Injection / Middleware: Is the vulnerability in an actual execution path, or just an unused schema definition?
2. RAG Pipelines: Can the untrusted input reach persistent vector store write paths, or only read/query paths?
3. Tool Execution / MCP: Is the tool callable from unauthenticated external sources, or only via authorized local agent connections?
4. Frontend: Is the finding in a component that renders unsanitized user-generated content, or internal application state?

---

PRECEDENTS

1. Standard identifiers and UUIDs are not user-controlled injection vectors when properly parameterized in ORM/SQL queries.
2. User-provided architectural, text, or file inputs ARE untrusted and MUST be sanitized before execution or shell invocation.
3. Python `subprocess` calls for running internal scripts (`.agents/scripts/`, `.claude/scripts/`) are expected — only flag if they concatenate unsanitized user input into shell strings.
4. JWT / OAuth2 middleware standard implementations are assumed valid unless there is a concrete logic bypass or missing signature validation.
