## commands/ vs workflows/ — Why Two Directories

This distinction matters and Claude Code treats them differently.

**`workflows/`** — Internal procedures invoked by the AI during its own reasoning. These are loaded and followed as instructions. No special frontmatter required. Claude decides to run them based on context or user command.

**`commands/`** — True Claude Code slash commands registered with the CLI. These require the `allowed-tools` and `description` frontmatter block at the top. They are surfaced in Claude Code's command palette and can use bash interpolation (`!` syntax) to inject live shell output into the prompt context at invocation time.

`security-review.md` must be in `commands/` because it uses:
```yaml
---
allowed-tools: Bash(git diff:*), Bash(git status:*), Bash(git log:*)...
description: Complete a security review of the pending changes on the current branch
---
```
and the `!`git diff --merge-base origin/HEAD`` interpolation syntax. In `workflows/`, this syntax is ignored.

## Data Flow

```
User types /security-review
        ↓
Claude Code reads .claude/commands/security-review.md
        ↓
Bash interpolation runs: git diff, git status, git log
        ↓
Diff content injected into prompt
        ↓
Phase 1: Sub-task agent scans using custom-scan-instructions.txt categories
        ↓
Phase 2: Parallel sub-tasks filter using false-positive-filtering.txt rules
        ↓
Phase 3: Findings with confidence < 8 dropped
        ↓
Security report output
        ↓
/log triggered → DEVLOG.md updated with SECURITY entries
```

```
User completes any implementation session
        ↓
Claude auto-detects: bug fixed / feature added / edge case found
        ↓
Reads .claude/workflows/log.md
        ↓
Reads current docs/DEVLOG.md
        ↓
Appends structured entry (CHANGE / BUG / EDGE_CASE / SECURITY / DECISION / BLOCKED)
        ↓
Updates summary table at top of DEVLOG.md
```

## Skill Structure Reference

Each skill follows this internal layout:

```plaintext
skill-name/
├── SKILL.md           # Required — metadata, instructions, loading protocol
├── scripts/           # Optional — Python/Bash executables
├── references/        # Optional — cheatsheets, templates, docs
└── assets/            # Optional — images, logos
```

Claude reads `SKILL.md` before writing code for that domain. Scripts in `skills/*/scripts/` are invoked directly via Bash tool. Master scripts in `scripts/` orchestrate across all skills.
